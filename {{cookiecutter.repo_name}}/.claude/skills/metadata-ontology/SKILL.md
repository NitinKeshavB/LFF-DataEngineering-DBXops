# Metadata and ontology

Read `.claude/context/03_Architecture/Metadata_Model.md` and `.claude/context/04_Spec_Reference/Spec_Conventions.md` first; this skill is the working loop.

## The loop for a new or changed table

1. Put the table's spec under `bundles/<bundle>/src/dataflows/<layer>/dataflowspec/`, with `schema_path`, and `tags.data_domain` /
   `tags.data_product` on the spec. The data domain must be a **data-domain path** from `metadata/_platform/domains.yaml`
   (`business__sub__data`, e.g. `claims__litigation__claim_litigation`). A wrong path is rejected with "did you mean" suggestions;
   never invent one and never pass a business-domain or sub-domain path for a table.
2. `make sync-substitutions` then `make contracts`. Never hand-edit the machine-owned parts of a contract (servers, schema object, property
   physical fields, expectation-derived quality rules); edit the spec and regenerate.
3. Fill the human-owned fields: `description` (replace every `PLACEHOLDER-...`), `status`, property `primaryKey`/`businessName`/`description`/`classification`, semantic
   assignments (a URL that exists as a concept in `metadata/_platform/glossary.ttl`).
4. Expose the contract as an output port of **exactly one** product (`src/products/*.odps.yaml`, port `contractId`, `dbx.assetId`).
5. Bump the contract's `version` when content changes (major when a column is removed or retyped): `BASELINE=origin/main make validate-metadata`.
6. `make validate-metadata` must report 0 errors. A table written by a **job** rather than a spec gets a hand-written contract with
   `dbx.producer: job` on its schema object.

## Rules that surprise people

- `metadata/_platform/` is generated by the registry and hash-protected: never edit it; request a change through the registry.
- A table in a **Restricted** data domain must carry `classification: restricted` (new contracts get it automatically).
- Ids carry the project: `dc_<project_id>_<layer>_<table>`, `dp_<project_id>_<name>`; schemas are `<project_id>_<layer>`.
- A squad writes only rows with its own `repo_id`; organisation records (domains, squads, projects, glossary) belong to the registry.
- Quality results match contract rules by `<table>_<slug of expectation name>`; renaming an expectation renames its rule.

## Publishing and exporting

`python -m dbxops.metastore publish --target <t>` (squad records), `publish-registry` (registry), `make export-ontos TARGET=<t>` (Ontos files).
Details: `.claude/context/06_Operations/Metadata_DB.md`, `Ontos_Onboarding.md`. What is unverified live: `Known_Gaps.md`.
